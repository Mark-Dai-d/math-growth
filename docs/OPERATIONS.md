# 上线验收与长期维护

## 发布前检查

- [ ] 在空 Supabase 项目应用 migration，确认所有业务表启用 RLS。
- [ ] 关闭公开注册与匿名账号创建；手动创建并授予唯一管理员角色。
- [ ] 前端配置使用实际 Project URL 和 `sb_publishable_` key，仓库没有密码、高权限 key 或真实学生示例。
- [ ] 执行 `pnpm check`、`pnpm test`、`pnpm test:database`、`pnpm build`。
- [ ] 执行 `pnpm test:e2e`，核对桌面与手机界面、公开页和 Hash 路由。
- [ ] GitHub Pages Source 为 GitHub Actions，部署工作流绿色，URL 与真实仓库匹配。

## 云端验收

这些检查在你自己的云端项目完成，测试记录可使用虚构姓名。无真实云端项目时只能报告本地检查通过。

1. 使用管理员邮箱密码登录，新增学生和周记录；刷新、退出后重新登录，记录仍然存在。
2. 用无痕窗口访问公开首页；未发布的学习趋势不出现，原始姓名、成绩和课堂反馈不能读取。
3. 在无痕窗口开发者工具中尝试 Supabase REST API 读取 `students` / `weekly_records`：请求应被对象权限拒绝，或因行级策略返回空记录；不能出现私有数据。
4. 用未经 `admin_roles` 授权的测试账号登录（通过控制台创建）：不能读取私有数据，不能新增积分，不能自授管理员。
5. 管理员新增同月至少三条有效记录，并添加请假、未授课、待测评记录；预测平均只包含有效记录。
6. 录入满分不同、得分率提高的对比考试；只有勾选可比性才加分，同月不超上限。
7. 月度结算后刷新，快照与奖励存在。改写历史周记录，原结算保持不变；重新结算必须填写原因，修订与审计可查，同一结算不重复发奖励。
8. 主动发布匿名摘要，无痕窗口可见；撤回后不可见。重新结算后旧摘要自动撤回，核实新快照后需主动重新发布。
9. 使用奖励，检查余额减少；请求超出余额时失败。非优秀月份与规则修改不清空历史奖励。人工补发或纠正必须填写原因，扣减不能导致负余额，流水和审计可查。
10. 手机宽度下完成一次周记录录入；每个字段有标签，评分不依赖颜色，弹窗与导航可操作。
11. 直接打开并刷新 `/<仓库名>/#/admin/weekly`，页面正常显示；未登录时进入登录入口。

需要直接验证 REST 权限时，以 publishable key 作为 `apikey` 请求头；登录场景还要使用当前 Auth session 的用户 access token 作为 `Authorization: Bearer ...`，不要拿 publishable key 当用户 JWT。测试只使用虚构记录，不把 token 保存到仓库或截图中。

## 备份与恢复

学习记录导出可用于日常查阅；完整恢复需要数据库备份，包含规则版本、结算快照、奖励流水、公开发布状态和审计日志。Supabase 的备份能力取决于实际项目配置，按控制台确认你的保留与恢复方案。[Supabase 数据库备份说明](https://supabase.com/docs/guides/platform/backups)

建议每月结算后导出查阅文件，并在重要规则或数据库变更前做数据库备份。使用 Supabase 控制台或受控的数据库工具，不在浏览器中配置高权限密钥来备份。备份存放在受保护位置，进行加密和访问限制，避免进入 Git 或公开文件分享。

至少每学期在独立测试项目恢复一次：检查学生与周记录条数、规则版本关联、月度快照、奖励余额、公开状态、RLS 和 Auth 用户授权。数据库备份与 Auth 用户 / 认证配置的恢复范围应按所选方法核对，不能假定复制业务表就恢复了登录。

## 日常维护

- 每周：记录授课与考试，使用未完成状态表达尚未测评，避免录入虚假零分。
- 每月：复核有效记录、确认考试可比性、结算、核对奖励、选择是否发布匿名摘要、备份。
- 每学期：录入学期评价与大奖，核对奖励使用流水，做一次恢复演练。
- 修改规则：优先从下月 1 日生效；保留历史版本，说明评分细则变化。
- 修改历史结算：先核对原始记录和原因，再确认重算，随后检查并决定是否更新公开摘要。
- 更新依赖或迁移：先在本地与独立测试项目验证，再发布；锁文件与 migration 一起纳入代码评审。

## 故障处理

网站白屏或路由 404：先检查 Actions 构建 / 部署状态与浏览器控制台，然后检查 Pages Source、Vite base 和访问路径。登录失败：检查邮箱密码、账号确认状态、项目 URL 和 Supabase Auth 服务；登录成功但未授权：核对 `admin_roles`。

写入失败：根据应用错误提示检查字段、外键和约束，确认 migration 已应用到实际项目，不要关闭 RLS 来临时绕过。月度数字与预期不同：先检查记录状态、自然月日期、规则版本、考试可比性和对比得分率；确认完整精度计算后再决定是否重算。

发现误发布：管理员先撤回匿名摘要；公开内容只能使用预设匿名字段，私有原始记录不通过该发布入口流出。发现权限配置被手工改变：恢复受版本管理的策略，在独立测试项目复测后恢复使用。

## 当前外部配置状态

交付时用户尚未创建 GitHub 仓库与 Supabase 项目。已提供初始化 SQL、前端环境模板、自动工作流和本地验证；尚需用户创建项目、应用 migration、创建并授权 Auth 用户、填入公开配置、推送仓库并启用 Pages。完成这些配置后，按本页云端验收确认真实数据与权限。
